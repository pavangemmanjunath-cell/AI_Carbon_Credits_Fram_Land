# Privacy design

A farm boundary is personal data. In many places it identifies the owner
as surely as a name, and it reveals assets, land disputes and livelihoods.
AgriCarbon Atlas is therefore built so that exact geometry stays with its
owner, public views see a generalized location, calculations never need
coordinates, and the optional AI explanation never receives them.
CLAUDE.md principle 11 states the rule; this page shows how it is applied.

## Public vs private data

| Data | Classification | Who can see it | Where it is stored | Notes |
|---|---|---|---|---|
| Plot polygon (`geometry`) | **Private** | Owner only (API key / session) | Repository (memory or PostGIS) | Never in logs, reports for third parties, share links or `/explain` |
| Exact centroid (`centroid`) | **Private** | Owner only | Repository | Used for climate and soil lookups by the API |
| `public_centroid` (0.05° grid) | Public-safe | Anyone the owner shares with; public map if a deployment enables one | Repository | About 5.5 km N–S; places a plot in a district, not on a parcel |
| Area, perimeter | Private by default | Owner; may appear in shared reports | Repository | Area plus public centroid is acceptable; area plus exact shape is not |
| Country, state/region/district | Public-safe | Shared views | Repository | Admin-level labels from reverse geocoding |
| Land-cover shares, NDVI/NDMI values and trend, climate zone, SOC | Derived indicators | Shared views, reports, `/explain` | Repository / cache | Do not reveal location on their own |
| Cube (12 × 12 × 36) with `grid.bbox` | **Private** | Owner only | Cache | The bbox is location; the cube endpoint is owner-scoped |
| Tree inventory | Private | Owner; aggregate in shared reports | Repository | Species, counts, ages are not location, but combined with district they narrow identity |
| Carbon estimate, readiness, policy screening | Derived | Owner; shareable | Repository | Contains plot id, never geometry |
| Market scenario | Derived | Owner; shareable | — | Illustrative |
| Reports | Owner-controlled | Whoever receives the file | `ATLAS_REPORTS_DIR` / bucket | Contain `public_centroid` and a static map at district scale unless the owner selects "include exact boundary" |
| Cached rasters (WorldCover, Sentinel-2 windows) | **Private** | Server only | `ATLAS_CACHE_DIR` / cache bucket | Window extent equals the plot bbox; treat as personal data with retention limits |
| Simulation share link | Public | Anyone with the link | — | Country, species, trees, year, horizon only |
| Access logs | Operational | Operators | Edge / API logs | Plot ids and timings; never coordinates |

## The generalized centroid

`public_centroid` is the exact centroid rounded to the nearest multiple of
0.05° in latitude and longitude. The step was chosen so that the
generalized point is clearly not a parcel location in every supported
region (5.5 km in latitude; in longitude about 5.4 km at 13° N, 4.0 km at
44° N and 1.9 km at 70° N) while remaining useful for district-level statistics, regional
maps and climate lookups where sub-kilometre precision adds nothing. The
rounding is deterministic (no jitter), so repeated requests cannot be
averaged back to the exact point. Rationale and edge cases are in
[geolocation.md](geolocation.md).

## Deterministic mode and AI-assisted mode

The platform runs the same way whether or not an AI explanation provider
is configured; the only difference is who writes the explanatory
paragraph.

| | Deterministic (default) | AI-assisted (opt-in) |
|---|---|---|
| Switch | `ATLAS_EXPLAIN_PROVIDER=template` | `ATLAS_EXPLAIN_PROVIDER=llm` plus `LLM_API_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` |
| Carbon numbers | Computed by the engines | Computed by the engines — unchanged |
| Policy screening | From `config/policies/` | From `config/policies/` — unchanged |
| Explanation text | Rendered from templates per language | Generated by the configured model from the same indicator payload |
| Data sent to a third party | None | The indicator payload only (see below) |
| Label in the UI | "Explanation" | "AI-generated explanation — based on derived indicators only" |

A deployment that enables the LLM provider should name the provider in
its privacy notice ([farmer-data.md](farmer-data.md)).

## What `/explain` receives

The request schema for `POST /explain` accepts a `language` and an
`indicators` object with keys such as `area_hectares`, `tree_count`,
`species`, `ndvi`, `ndvi_trend_pct`, `estimate_central`, `estimate_low`,
`estimate_high`, `confidence` and `missing_evidence`. The schema
**rejects** any key named `lat`, `lon`, `latitude`, `longitude`,
`geometry`, `coordinates` or `polygon`, at any nesting level, with a 422
problem. Country and region names are also excluded by default; a
deployment may allow the country code if its explanations need it, but
never district names together with area and species. The response carries
a `privacy_note` stating that only derived indicators were used. The
front end builds this payload from the results view, never from the plot
object, and the end-to-end suite checks it
([../../tests/e2e/README.md](../../tests/e2e/README.md)).

## Logging and error handling

Structured logs include request id, route, plot id, mode, timings and
outcome. A redaction filter drops any field whose name suggests location
and scans message strings for decimal-degree pairs; a unit test feeds the
logger a request with coordinates and asserts they do not appear. Error
responses (RFC 7807) describe the validation failure without echoing the
geometry ("ring is not closed" rather than the ring).

## Upstream disclosure

Bounding boxes and centroids are sent to Earth-observation, climate and
soil providers because that is how data for a location is fetched
([../architecture/data-flow.md](../architecture/data-flow.md)). The API
sends them without user identity, caches the results so the disclosure is
not repeated, and documents each provider in
[../licensing/DATA_LICENSES.md](../licensing/DATA_LICENSES.md). Deployers
who require that no coordinates leave their infrastructure can run demo
mode, self-host the datasets (WorldCover and Sentinel-2 archives are
downloadable), or configure self-hosted geocoders.
